変数と番地

ねこ博士
この道場で目指すことを先に言っておこう。『メモリのしくみクエスト』で、番地・スタック・ヒープ・ポインタの考え方は見てきたね。ここでは、それを実際の C言語のコードで書いて、1行ごとにメモリの中で何が起きているかを正確に追えるようにする。
この道場で解きたい問題 分かっているもの：メモリは番地付きの箱の列。関数の変数はスタック、malloc で借りたものはヒープ。ポインタは番地をしまう変数 知りたいもの：C言語の1行1行が、どの箱をどう書き換えるのか。どこで間違えると壊れるのか ゴール（STAGE8）：連結リストから値を1つ消す関数 deleteNode を、自分で完成させる 道順：変数と番地（1）→ 配列（2）→ ヒープ（3）→ 構造体（4）→ ポインタのポインタ（5）→ 連結リスト（6）→ よくある間違い（7）→ 総合稽古（8）

前のクエストでは、x を 0x20 番地のように、分かりやすい番地で考えていました。本物のコンピュータでは、どんな番地になるんですか？
ねこ博士
いまのパソコンは64ビットの CPU だから、番地は8バイトの数で、ふつう12桁くらいの16進数になる。0x7ffd3a2c0e6c のようにね。スタックはこのような大きな番地のあたりに、ヒープはもっと小さい番地のあたりに置かれることが多い。まずは一番かんたんなプログラムを読もう。
#include <stdio.h>　画面に表示する printf などの道具を使うための宣言（これを書かないと printf は使えない） int main(void) { … }　プログラムが最初に動かす関数 printf("%d\n", a);　a を10進数で表示する。%d は「ここに整数を入れて表示」、\n は改行
うさ美
int は4バイトの整数でしたよね。
ねこ博士
多くの環境では4バイトだけれど、実は C言語の決まりでは「少なくとも2バイト」としか決まっていない。何バイトかは、コンパイラと CPU の組み合わせ（環境）が決めるんだ。だから C言語には、型や変数の大きさを調べる sizeof がある。sizeof(int) と書けば、その環境での int の大きさが分かる。この道場では、いちばんよくある64ビットの環境（int は4バイト、ポインタは8バイト）で考える。
ねこ博士
では、番地を取り出して、ポインタで書き換えるコードを動かそう。番地を表示するときは %p を使い、番地を (void *) という「何を指すか決めていない番地」の形に直して渡すのが決まりだ。
うさ美
p に入っているのは a の番地で、*p と書くと a そのものになる。前のクエストの約束が、そのままコードになっていますね。
ねこ博士
そう。ここでよくある書き間違いを1つ。int *p, q; と書くと、ポインタになるのは p だけで、q はふつうの int になる。* は型ではなく、名前の側にくっつくんだ。だから、ポインタの宣言は1行に1つずつ書くのが安全だ。
うさ美
宣言したまま何も入れていないポインタは、どこを指しているんですか？
ねこ博士
関数の中で int *p; とだけ書いたポインタには、その場所にたまたま残っていた、でたらめな値が入っている。どこを指しているか分からないポインタをワイルドポインタ（野放しのポインタ）と呼び、その先を読み書きすると何が起きるか分からない。だから、まだ指す先が無いときは NULL（どこも指していないことを表す決まった値）を入れておく。
int *p = &a;　p に a の番地を入れる（p は a を指す） *p　p の指す箱（ここでは a）。読むことも書くこともできる int *q = NULL;　まだどこも指さない。何も入れないまま使うのは危険

確認クイズ

Q1. int a = 10; int *p = &a; *p = 30; のあと、a と p はどうなっている？

正解！ *p は「p の指す箱」なので、a に 30 が書かれる。p の中身（a の番地）は変わらない。

Q2. sizeof(int) の値について正しいのは？

正解！ C言語の決まりは「少なくとも2バイト」まで。多くの環境で4だが、決めつけずに sizeof で調べる。

Q3. 関数の中で int *p; とだけ書いて、すぐに *p = 5; とすると？

正解！ 初期化していないポインタはワイルドポインタ。使う前に、指す先の番地か NULL を必ず入れる。
