ポインタのポインタ

関数から呼び出し元を書き換える
🎯 ミッション
C言語の引数が「値のコピー」であることと、ポインタのポインタが必要になる理由を説明できるようになろう。2つのコードを最後の行まで実行し、確認クイズに全問正解すれば合格。
未達成
ねこ博士
今日の問題はこうだ。「int を1つヒープに借りて、42 を入れて、その番地を呼び出し元に渡す関数 allocate を作りたい」。main では int *p = NULL; を用意しておいて、allocate を呼んだら p がその場所を指すようにしたい。
うさ美
ポインタを渡せば、関数の中から書き換えられるんでしたよね（『メモリのしくみクエスト』）。だから void allocate(int *out) にして、中で out = malloc(…)。呼ぶときは allocate(p)。
ねこ博士
まず、その書き方で動かしてみよう。
うさ美
p は NULL のまま……。out は p のコピーだから、out を書き換えても p は変わらないんですね。しかも借りた場所の番地を誰も覚えていないので、リークまで起きている。
ねこ博士
そう。C言語の引数は、いつでも値のコピーだ。前のクエストで「番地を渡せば、呼び出し元の変数を書き換えられる」と言ったのは、書き換えたい変数そのものの番地を渡すという意味だった。いま書き換えたい変数は何かな？
うさ美
main の p です。p は int * 型の変数だから、p の番地 &p を渡せばいい。……p の番地を入れる変数の型は、「int * を指すポインタ」になりますね。
ねこ博士
それを int **（int を指すポインタを指すポインタ）と書く。関数の中では、*out が「out の指す箱」、つまり main の p そのものになる。
void allocate(int **out)　／　呼ぶとき：allocate(&p); out：p の番地　→　*out：p そのもの　→　**out：p の指す int
うさ美
「書き換えたいものの番地を渡す」という1つの規則を、ポインタにもそのまま当てはめただけなんですね。int を書き換えたいなら int *、int * を書き換えたいなら int **。
ねこ博士
そういうこと。* が2つ並ぶと怖く見えるけれど、規則は同じだ。別の方法として、関数の答え（return）で番地を返す int *allocate(void) という書き方もよく使われる。どちらも、番地を呼び出し元に確実に届けるための方法だ。
ねこ博士
int ** は、ほかにも出てくる。たとえば、行ごとに長さの違う表を作るときは、「行の先頭の番地」を並べた配列を借りて、それぞれの行を別に借りる。int **grid の grid[i] が i 行目の番地、grid[i][j] がその中の値になる。

確認クイズ

Q1. STAGE5 の「うまくいかない版」で、main の p が NULL のままだった理由は？

正解！ 引数はコピー。p 自身を書き換えたいなら、p の番地（&p、型は int **）を渡す。

Q2. void allocate(int **out) を allocate(&p) で呼んだとき、関数の中の *out は何を表す？

正解！ out には p の番地が入っている。*out は「out の指す箱」＝ p。**out はさらにその先の int。

Q3. うまくいかない版では、メモリリークも起きていた。その理由は？

正解！ 番地を覚えているものがなくなると、返すことができない。これがリーク。
