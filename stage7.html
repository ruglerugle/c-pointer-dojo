STAGE 7

バグ道場

6つの典型的な間違い
🎯 ミッション
ポインタの典型的な6つの間違いを、コードから見抜けるようになろう。間違ったコードを最後の行まで実行し、6問の確認クイズに全問正解すれば合格。
未達成
ねこ博士
ここまでで、正しい書き方は一通りそろった。今日は逆に、間違いを見抜く稽古をする。C言語のポインタの間違いは、コンパイラが見逃すことが多く、しかも未定義動作なので、たまたま動いてしまう。だから、コードを読んで見抜く目が必要なんだ。
うさ美
種類ごとに、名前と、何が起きるかを整理しておきたいです。
ねこ博士
いいね。まとめるとこうなる。
① 解放後の使用：free した場所を、残っていた番地で読み書きする ② 二重解放：同じ場所を2回 free する。ヒープの管理係の名簿が壊れる ③ メモリリーク：返さないまま番地を失う ④ 範囲外の読み書き（バッファあふれ）：配列の大きさを超えた添え字を使う ⑤ 初期化していないポインタ（ワイルドポインタ）：でたらめな番地の先を使う ⑥ NULL の確かめ忘れ：malloc の失敗を確かめずに使う

うさ美
動いてしまうのが一番怖いですね。テストで見つからないまま、本番でだけ壊れるかもしれない。
ねこ博士
そう。だから、間違いを見つける道具も使う。コンパイラに警告を全部出させる、AddressSanitizer のように「返した場所や範囲外を読んだ瞬間に止める」検査つきで動かす、などだ。でも一番の土台は、コードを読んで見抜く目だ。では、6つのコードを見て、それぞれの間違いを当てよう。

確認クイズ

Q1. このコードの間違いは？

int *p = malloc(sizeof(int));
if (p == NULL) return 1;
*p = 5;
free(p);
printf("%d\n", *p);

正解！ free の後も p の中身は残っている。その番地を *p で読むのは解放後の使用。free の後に p = NULL; を入れておけば気づきやすい。

Q2. このコードの間違いは？

int *p = malloc(sizeof(int));
if (p == NULL) return 1;
free(p);
free(p);

正解！ 同じ場所を2回返すと、空きの名簿に2回載り、あとで同じ場所が2人に貸される。1回目の free の直後に p = NULL; にしておけば、free(NULL) は何もしないので防げる。

Q3. このコードの間違いは？

void f(void) {
    int *p = malloc(sizeof(int) * 10);
    if (p == NULL) return;
    p[0] = 1;
}   // free せずに終わる

正解！ 関数が終わると p は板ごと消え、借りた40バイトの番地をだれも覚えていない。返すことができずに取り残される。

Q4. このコードの間違いは？

int arr[5];
for (int i = 0; i <= 5; i++) {
    arr[i] = i;
}

正解！ arr の添え字は 0〜4。i <= 5 だと arr[5]、つまり配列のすぐ後ろの番地に書き込んでしまう。条件は i < 5 が正しい。

Q5. このコードの間違いは？

int *p;
*p = 10;

正解！ 関数の中で宣言しただけのポインタには、でたらめな値が入っている（ワイルドポインタ）。どこに書くか分からない。

Q6. このコードの間違いは？

size_t n = 1000000000000;   // とても大きい
int *p = malloc(sizeof(int) * n);
p[0] = 1;

正解！ 大きすぎる要求は失敗して NULL が返ることがある。確かめずに p[0] へ書くと、NULL の先を使う未定義動作。
