配列とポインタ演算

arr[i] と *(arr + i)
🎯 ミッション
配列とポインタの関係（先頭番地への変換・ポインタ演算・添え字）を説明できるようになろう。コードを最後の行まで実行し、確認クイズに全問正解すれば合格。

ねこ博士
配列は、同じ型の箱を番地の連続した場所に並べたものだったね。int arr[4] = {10, 20, 30, 40}; と書くと、4バイトの int が4つ、隙間なく並ぶ。
うさ美
先頭の arr[0] の番地が分かれば、arr[1] は4バイト先、arr[2] は8バイト先ですね。
ねこ博士
そう。そして C言語には、配列について大事な約束がある。配列の名前を式の中で使うと、たいていの場合「先頭要素の番地」に変わる。だから int *p = arr; と書くと、p には arr[0] の番地が入る。
うさ美
「たいていの場合」というのは、変わらない場合もあるんですか？
ねこ博士
2つある。sizeof arr と書いたときと、&arr と書いたときだ。sizeof arr は配列全体の大きさ（int 4つで16バイト）になる。もし番地に変わってしまっていたら、ポインタの大きさの8になるはずだね。&arr は「配列全体の番地」で、値は arr[0] の番地と同じだけれど、「16バイトのかたまりを指す」という意味になる。
arr（式の中）→ &arr[0]、つまり先頭要素の番地に変わる 例外1：sizeof arr は配列全体の大きさ（4×4＝16バイト） 例外2：&arr は配列全体を指す番地（値は先頭と同じ、意味が違う）
ねこ博士
ポインタの足し算は、指している型1個分ずつ進むんだったね。int を指す p なら、p + 1 は番地として4バイト先。そして arr[i] という書き方は、C言語の決まりでは *(arr + i) とまったく同じ意味だと定められている。
うさ美
arr[2] が *(arr + 2) と同じ意味なら、2[arr] と書いても *(2 + arr) で同じになりませんか？ 足し算は順番を入れ替えても同じだから。
ねこ博士
実際に、C言語ではそれも正しく動く。決まりをそのまま当てはめた結果なんだ。もちろん読みにくいので、本当に書く人はいないけれどね。
うさ美
配列の外、たとえば arr[4] や arr[10] と書いたらどうなるんですか？
ねこ博士
計算としては *(arr + 4) だから、arr[3] のすぐ後ろの番地を読み書きしてしまう。C言語は、添え字が範囲の中かどうかを確かめない。そこに別の変数があれば、それを壊す。これは STAGE7 のバグ道場で詳しく扱う。
ねこ博士
最後に、関数に配列を渡すときの注意だ。void f(int a[]) と書いても、関数が受け取るのは先頭の番地だけで、中身はポインタ int *a と同じになる。だから、関数の中で sizeof a としても配列の大きさは分からない。
うさ美
番地だけ渡されても、何個並んでいるかは分からない……。だから、配列を渡す関数には、要素の数も一緒に渡すんですね。
ねこ博士
そう。void f(int *a, size_t n) のように、個数を別の引数で渡すのが C言語の決まった書き方だ（size_t は大きさや個数を表すための、マイナスにならない整数の型）。

確認クイズ

Q1. int を指すポインタ p に 1 を足すと、番地はいくつ進む（int が4バイトの環境）？

正解！ ポインタ演算は「指す型1個分」単位。int なら4バイト進み、次の要素を指す。

Q2. int arr[4]; のとき、sizeof arr の値は（int 4バイト、ポインタ8バイトの環境）？

正解！ sizeof の中では、配列の名前は番地に変わらない。int 4つ分の16。

Q3. 関数 void f(int a[]) の中で a について正しいのは？

正解！ 配列を関数に渡すと、先頭の番地に変わる。要素の数は別の引数で渡す。
